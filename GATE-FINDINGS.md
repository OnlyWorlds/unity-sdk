## UPHELD — attacked and unbroken (do not re-verify)

**The design holds.** Both candidate-fatal assumptions were confirmed against shipped artifacts, not
belief:

- **Generic struct serialization works.** Unity's own manual, verbatim: *"Generic field types can
  also be directly serialized, without the need to declare a non-generic subclass."*
  `[SerializeField] private` inside the generic struct qualifies.
- **★ Open-generic PropertyDrawer resolution works.** The lens decompiled the *installed*
  `UnityEditor.CoreModule.dll`: `TryGetDrawerTypeForTypeFromCache` falls back to
  `GetGenericTypeDefinition()` on a miss, so `typeof(SerializableNullable<>)` resolves. **Web and
  forum sources say this is unsupported — they are stale, and shipped code overrode them.** This was
  my single biggest worry and it is answered.
- **The core three-state contract genuinely works**: unset→`null`, zero→`0`, all three read states
  correct, a realistic PATCH round trip preserves `null`. `Equals` proven non-vacuous against a
  deliberately broken implementation. `PopulateObject` merge semantics right.
- **asmdef Newtonsoft pattern is byte-for-byte Unity's own** `com.unity.ide.visualstudio`.
  `nunit.framework.dll` + `UNITY_INCLUDE_TESTS` match Unity's `Unity.AI.Navigation.Tests`.
- `ConcurrentDictionary` + C# 9 `static` lambda: fine, no Burst exposure.
- The no-implicit-conversion-back decision and the JSON three-state semantics were called the
  strongest parts of the design.
- Nice accidental property: **forgetting `OWJson` throws loudly** rather than failing silently,
  because the throwing `Value` getter acts as a tripwire when Newtonsoft reflects over the struct.

### ⚑ The trap this run walked into, and the law that comes out of it

The FIRST run reported `total: 0 ... resultState: "Passed"`. **A green suite that ran nothing.**

Cause: the tests lived in `Tests/Runtime/` under an asmdef with empty `includePlatforms`, which
makes it a *runtime* assembly — and EditMode does not collect runtime-assembly tests. Nothing was
wrong with the tests; nothing ran them.

Fixed by moving all tests to `Tests/Editor/` (they are pure logic -- no scene, no frames, no
coroutines, so EditMode is where they belong) and aligning the namespace to
`OnlyWorlds.Sdk.Tests.Editor`. The `Tests/Runtime/` asmdef stays for future tests that genuinely
need the game loop.

**Standing law: check the test COUNT, not just the verdict.** A zero-count pass is the most
dangerous suite result there is, because it is indistinguishable from success at a glance.

   realValue:        { _value: 42, _hasValue: 1 }

   unsetBool:        { _value: 0,  _hasValue: 0 }
